データレイクやデータウェアハウスのデータ格納アーキテクチャの 1 つです. [^medallion_google][^medallion_databricks]

## 概要

メダリオンアーキテクチャでは, データを次の 3 層に区分して保持します.

| 区分         | 保持するもの                                             |
| :----------- | :------------------------------------------------------- |
| Bronze Layer | 未処理の生データ, 不変に未整形のデータを保持する         |
| Silver Layer | クレンジングや整形処理を施したデータを保持する           |
| Gold Layer   | 集計済み, すぐにビジネス用途に利用できるデータを保持する |

## 構成

### Bronze Layer

IoT からのセンサーデータや各種 API 応答, 非構造化データに至るまで, 生データをそのままの形態で取り込む層です.
この層を配置するメリットは「変換プロセスと生データの分離」です.

従来の ETL ソリューションを実行してデータを流し込む場合, この ETL プロセス自体に誤りがあったり, エラー発生時に再チェックが困難となったりする場合がありました.
生データを変換プロセスを挟まずに保持することで, 変換プロセスの誤りやエラー時にいつでも再試行したり, そのプロセス自体を検証することが可能となり, プロセス自体の信頼性を高めることができます.

また, 変換プロセスを変更しようとする際に, 変換後のものしか持たない場合は再度データの取得が必要となったり, そもそもデータが残っておらず再取得ができず変更困難となったりする場合がありました.
この場合においても, 変換前の生データを保持することによって, プロセスの変更にも対応が効くようになります.

### Silver Layer

単純なデータクレンジングや正規化/標準化, データ型の変換や重複除去などの事前処理を行う層です.
この層は後の Gold 層へ至る前に, 多くのユースケースで共通して必要になる前処理が適用された信頼できる情報源として利用されます.

この層を配置するメリットは「変換プロセスの統括」です.
Bronze Layer に生データはありますが, これを集計データを起こす際に毎回変換処理を記述するのはクエリ実装コストの面で無駄が大きく生じますし, 同様の変換テーブルの乱立も招きます.
データについては事前に正規化/標準化されたデータを元に集計することで, クエリ実装コストを低減しつつ, データ分析時の揺れや齟齬を生じる可能性を低減できます.

### Gold Layer

言わずもがなの集計済み, すぐ使えるデータ群を配置する層です.
特定の用途や分析に特化し, そのデータを利用したいユーザに合わせて最適化されます.

この層は単純にデータを利用するユーザのために配置されます.
BI ツール的に利用される場合には, このレイヤに共通した集計ロジックを適用することで, 一貫して共通のロジックによって算出された主要なメトリクスを利用できるようになります.

## メダリオンアーキテクチャ 2.0

上記 3 層以外に「Agentic AI が利用するためのデータレイヤ」となる Plutinum Layer を加えたアーキテクチャです.
この Plutinum Layer に含まれるものとして次のような概念が追加されています. [^medallion_2_0]

- Agent がデータの意味を理解するための Semantic Layer や Knowledge グラフ
- セキュリティガバナンスなどによる保護

この構成は従来のデータ分析といったものよりも, 組織としてデータをどう活用するか, データをどう守っていくかという面にフォーカスした内容となっています.
