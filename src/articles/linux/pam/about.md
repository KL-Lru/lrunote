## 概要

Linux において, ユーザの認証を一元管理する仕組みとして PAM (Pluggable Authentication Modules) があります.

PAM は認証モジュール群を実行する仕組みとその設定方法を提供し, 実際にどのファイルを参照して認証するのか, どのホストから情報を取得するのかといった制御はモジュールとして取り込む形態を取ります.
この方式を取ることによって, 必要に応じて機能を追加できる柔軟な認証の仕組みを提供できます.

## モジュールの利用

PAM ではそのモジュールの実行フェーズ, モジュールの結果の取り扱い, 利用するモジュール, そしてその設定の組み合わせで認証処理を制御します.
フェーズとしては以下の 4 種が利用できます.

| フェーズ   | 内容                       |
| :--------- | :------------------------- |
| `auth`     | ユーザ認証自体             |
| `account`  | ユーザアカウントの状態確認 |
| `password` | パスワードの変更と設定     |
| `session`  | ユーザ認証前後の実行処理   |

モジュール結果の取り扱いについては, 次の 4 種の他, `[success=ok default=ignore]` などの細かな制御が設定できます.

| 制御         | 内容                                                                                                                                         |
| :----------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| `requisite`  | モジュールの結果が失敗の場合, 認証は拒否される <br> 失敗した段階ですぐに認証を拒否する                                                       |
| `required`   | モジュールの結果が失敗の場合, 認証は拒否される <br> 他のモジュールの実行を完了した後に認証を拒否する                                         |
| `sufficient` | モジュールの結果が失敗の場合, 無視される <br> 他の required なモジュールが失敗しておらず, かつこのモジュールの結果が成功した場合は認証される |
| `optional`   | 認証結果に影響をもたらさない (成否を問わない) <br> 同一の役割を有するモジュールが存在しない場合に限り, 成否が認証結果の成否に反映される      |

別のファイルから設定を読み込むなどする場合は `include` や `subtrack` が利用できます.
